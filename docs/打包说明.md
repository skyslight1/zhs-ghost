# 打包说明

面向想自己构建 exe、或者想改打包配置的人。
普通用户不需要看这个 —— 直接去 [Releases](https://github.com/skyslight1/zhs-ghost/releases) 下载即可。

---

## 1. 两个版本的区别

| | `zhs-ghost.exe`（完整版） | `zhs-ghost-lite.exe`（精简版） |
|---|---|---|
| 核心刷课功能 | ✅ | ✅ |
| 验证码**自动识别** | ✅ ddddocr + OpenCV | ❌ |
| 验证码**人工过** | ✅ 自动开浏览器等你滑 | ✅ 同左 |
| 浏览器内核 | 系统 Edge / Chrome | 系统 Edge / Chrome |
| 体积 | 约 200~350 MB | 约 25~40 MB |
| 首次启动 | 慢（单文件要解压） | 快 |

**为什么完整版这么大？** 因为塞进了 `onnxruntime`（15MB）、`opencv`（44MB）、
`ddddocr` 的识别模型、以及 `playwright` 的 node driver。

如果你不需要自动识别验证码（或者很少遇到），精简版体验其实更舒服 ——
体积小、启动快，遇到验证码浏览器一开你自己滑一下也就 3 秒。

## 2. 本地打包

```bash
pip install -r requirements.txt
pip install pyinstaller

python packaging/build.py lite        # 精简版单文件
python packaging/build.py full        # 完整版单文件
python packaging/build.py all         # 两个都出
```

产物在 `dist/` 下，同时会生成一个 zip（里面附带了使用教程和示例配置）。

**打包完会自动跑一次 `--dry-run` 自检** —— 确认 exe 真能启动，而不是打出个坏文件。
这一步在完整版上可能要花 1~2 分钟（单文件首次启动要解压）。

其他开关：

```bash
python packaging/build.py full --dir      # 目录形态，启动快，适合自己长期用
python packaging/build.py full --no-zip   # 不打 zip
python packaging/build.py full --no-test  # 跳过自检（不推荐）
```

### 目录形态 vs 单文件

| | 单文件 (`--no-dir`) | 目录 (`--dir`) |
|---|---|---|
| 分发 | 一个 exe，直接发 | 一个文件夹，要打 zip |
| 启动 | 慢，每次解压到临时目录 | 快 |
| 杀软误报 | 高一些 | 低一些 |

自己长期挂机用 → 选 `--dir`。给别人分享 → 选单文件。

## 3. CI 自动打包（推荐）

推 tag 就会自动构建并挂到 Release 上：

```bash
git tag -a v1.1.0 -m "v1.1.0"
git push origin v1.1.0
```

`.github/workflows/release.yml` 会：

1. 跑 106 项单元自测（**先证明源码是对的，再打包**）
2. 构建完整版和精简版
3. 逐个 exe 跑 `--dry-run` 自检
4. 检查产物体积（小于 1MB 说明依赖没打进去，直接失败）
5. 上传到 Release

也可以手动触发（Actions → release → Run workflow），那样只上传构建产物，不发 Release。

## 4. 打包时踩过的坑

留给后来改配置的人。

### 4.1 版本信息文件的参数名

`FixedFileInfo` 的参数名和直觉不一样，写错了 PyInstaller 会抛
`Failed to deserialize VSVersionInfo`：

```python
# ❌ 错的
FixedFileInfo(os=..., fileVersion=(1,0,0,0))

# ✅ 对的
FixedFileInfo(OS=..., filevers=(1,0,0,0), prodvers=(1,0,0,0), date=(0, 0))
```

`OS` 是大写，版本字段是 `filevers` / `prodvers`。

### 4.2 ddddocr 的模型文件要显式收集

`ddddocr` 的 `.onnx` 模型不在 Python 包里，是数据文件：

```python
datas += collect_data_files("ddddocr")
```

不收集的话打包能成功，但运行时一调就报找不到模型。

### 4.3 onnxruntime 的 DLL 不会自动收集

```python
binaries += collect_dynamic_libs("onnxruntime")
```

缺了它运行时报 `DLL load failed`。

### 4.4 playwright 的 node driver

`playwright` 依赖一个 node 二进制 + `cli.js`，在包数据里：

```python
datas += collect_data_files("playwright")
```

**但是**：浏览器内核本身（chromium ~150MB）不在里面，需要 `playwright install`。

这就是为什么 relay 默认优先用**系统自带的 Edge**：

```python
def channel_chain(self):
    if self.cfg.channel:
        return [self.cfg.channel]
    if self.cfg.prefer_system_browser:
        return ["msedge", "chrome", None]   # 逐个试，最后才用内置 chromium
    return [None]
```

Windows 10/11 一定有 Edge，所以打包版不需要用户再下载任何东西 —— 这是
"开箱即用"最关键的一步。

### 4.5 UPX 保持关闭

```python
upx=False
```

UPX 能让体积小 30%，但 Windows Defender 对 UPX 压缩过的 exe 误报率明显更高。
用户第一次双击就被杀软拦下来，体验比大 30MB 糟糕得多。

### 4.6 不必要的重依赖要排除

```python
excludes = ["tkinter", "matplotlib", "pandas", "scipy", "torch", "transformers",
            "openai", "tiktoken", "jupyter", "pytest", "tests"]
```

特别是 `transformers` / `torch` —— 如果开发环境里恰好装了，PyInstaller 的
分析器可能会顺着 import 链把它们拖进来，体积直接翻几倍。

本项目调用 OpenAI 兼容接口用的是 `requests` 直连，**不需要 `openai` SDK**，
可以安全排除。

## 5. 验证打包产物

```bash
# 逐项检查组件（推荐先跑这个）
dist\zhs-ghost.exe --selfcheck

# 看它会不会自动生成配置（真开箱即用的关键）
mkdir D:\test && copy dist\zhs-ghost.exe D:\test\
D:\test\zhs-ghost.exe --dry-run
dir D:\test          # 应该出现 config.yaml
```

`--selfcheck` 通过时会看到：

```
组件自检 · 完整版 · variant=full
  [ok]  配置解析       yaml
  [ok]  日志           loguru
  [ok]  网络请求       requests
  [ok]  请求加密       Crypto.Cipher.AES
  [ok]  图片处理       PIL.Image
  [ok]  浏览器中继      playwright
  [ok]  中继驱动       playwright._impl._driver
  [ok]  验证码识别      ddddocr
  [ok]  图像处理       cv2
  [ok]  OCR 推理引擎    onnxruntime
--------------------------------------------------------------------
  [ok]  系统浏览器      msedge → C:\Program Files (x86)\...\msedge.exe
  [ok]  playwright 驱动可调用
自检通过
```

精简版只检查前 5 项，后面那些是故意不打的。

`--dry-run` 的输出里注意标题栏的 `[完整版]` / `[精简版]` / `[源码版]` ——
这是 `paths.runtime_label()` 给出的，用来确认你跑的是哪个产物。

## 6. 目录约定（打包版）

```
你的目录/
├── zhs-ghost.exe          你已经下载的文件
├── config.yaml            首次运行自动生成
├── 使用教程.md             压缩包里附带
├── courses.json           --fetch 生成
├── state/                 登录态、配额、浏览器指纹
└── logs/                  日志
```

`app_root()` 在打包后返回 **exe 所在目录**，所以配置和状态都跟着 exe 走 ——
把 exe 连同目录一起搬到 U 盘，配置也一起搬走。
