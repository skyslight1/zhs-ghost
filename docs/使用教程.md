## 0. 三分钟上手

如果你只想尽快跑起来：

```
1. 下载 zhs-ghost.exe，放到一个单独的空文件夹里（别放桌面和下载目录）
2. 双击它 → 第一次会自动生成 config.yaml
3. 用记事本打开 config.yaml，什么都不用改，直接保存
4. 双击 zhs-ghost.exe → 终端里会打印一个二维码
5. 手机打开「知到」App 扫码登录
6. 登录成功后它会自动拉取你的课程并开始学习
```

**就这样。** 不需要填账号密码 —— 默认走扫码登录。

> 为什么放单独的空文件夹？程序会在旁边生成 `state/`（登录态、配额）
> 和 `logs/`（日志）。单独放一个目录，出问题时整个目录删掉就能重来。

## 1. 三种运行方式，选一个

### 方式 A：exe（推荐给不想碰 Python 的人）

从 [Releases](https://github.com/skyslight1/zhs-ghost/releases) 下载：

| 文件 | 说明 | 体积 |
|---|---|---|
| `zhs-ghost.exe` | **完整版**。内置验证码自动识别，开箱即用 | 大 |
| `zhs-ghost-lite.exe` | 精简版。核心功能齐全，但弹验证码时需要你手动滑 | 小 |

两个都用同样的命令，区别只在遇到人机验证时：

- 完整版：自动识别滑块/点选并过掉，失败才叫你；
- 精简版：直接开一个浏览器窗口，你自己滑一下就行。

**第一次运行**，双击即可。程序会在 exe 同目录生成 `config.yaml`。

**命令行用法**（把 `python main.py` 全部替换成 exe 的全路径）：

```powershell
.\zhs-ghost.exe --fetch            # 拉课程清单
.\zhs-ghost.exe -c 1919            # 刷课程 1919
.\zhs-ghost.exe --dry-run          # 只自检，不连网站
```

> Windows 首次运行可能弹「SmartScreen 已阻止」。点「更多信息」→「仍要运行」。
> 这是因为 exe 没有买代码签名证书，不是病毒。

### 方式 B：源码运行（推荐给想改代码的人）

```bash
git clone https://github.com/skyslight1/zhs-ghost.git
cd zhs-ghost

python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # macOS / Linux

pip install -r requirements.txt
python -m playwright install chromium

cp config.example.yaml config.yaml
python main.py --dry-run        # 自检
python main.py
```

### 方式 C：服务器挂机（Linux / 云主机）

```bash
# 第 1 步：装依赖
apt install -y python3 python3-pip
pip3 install -r requirements.txt
python3 -m playwright install --with-deps chromium

# 第 2 步：配置
cp config.example.yaml config.yaml
vim config.yaml     # 把 auth.use_qr 改成 true（默认就是）

# 第 3 步：登录（二维码在终端里，或者看 state/login_qr.png）
python3 main.py --fetch

# 第 4 步：后台跑
nohup python3 main.py > run.log 2>&1 &

# 第 5 步：看进度
tail -f run.log
```

如果服务器没有图形界面，把 `relay.headless` 改成 `true`：
自动识别仍然可用，只是**识别失败后你没法手动接管**（看不到窗口）。

## 2. 第一次使用：完整流程

### 2.1 拿到程序

- exe 用户：从 Releases 下载，放进一个空文件夹，比如 `D:\zhs-ghost\`
- 源码用户：按上面方式 B 做完

### 2.2 生成配置

**exe**：双击一次程序，`config.yaml` 会自动出现。
**源码**：`cp config.example.yaml config.yaml`

第一次看到 `config.yaml` 别慌，它长这样（节选）：

```yaml
auth:
  username: ""
  password: ""
  use_qr: true          # ← 默认扫码，不用改
  save_cookies: true

study:
  speed: 0              # 0 = 用默认速度（1.25x）
```

**你可以什么都不改。** 默认值就是一组调好的、不容易被风控盯上的参数。

### 2.3 登录

```bash
python main.py --fetch      # 或 .\zhs-ghost.exe --fetch
```

终端会出现：

```
▄▄▄▄▄▄▄ ▄▄ ▄▄▄▄▄ ▄▄▄▄▄▄▄
█ ▄▄▄ █ ▀█▄█▄▀▄ █ ▄▄▄ █
█ ███ █ ▄▀ ▄ ▀▀▀ █ ███ █
...
请用手机 App 扫描上方二维码（或打开 state/login_qr.png）
```

用手机「知到」App 扫码 → App 里点确认。

成功后会看到：

```
17:20:31 | INFO    | 二维码已扫描: 扫描成功
17:20:33 | INFO    | 已获取一次性登录凭证
17:20:34 | INFO    | 二维码登录成功
17:20:34 | INFO    | 登录完成，uuid=xxxxxxxx
17:20:35 | INFO    | 课程清单已写入 courses.json（6 门）
```

登录态会存进 `state/state.json`，**短期内不用重复扫**。
想重新登录：删掉 `state/state.json` 再跑。

> **为什么不用账号密码？**
> 智慧树对密码登录加了风控，失败几次就会要求验证码（`code -4`），
> 有些账号还会要求短信验证。扫码没有这些问题。

### 2.4 看看有什么课

上一步的 `courses.json` 就是你的课程清单：

```json
[
  { "type": "zhidao", "name": "中国近现代史纲要", "id": "a1b2c3d4e5f6..." },
  { "type": "hike",   "name": "高等数学",         "id": "1919" }
]
```

- `type: zhidao` = 共享课，`id` 是一长串带字母的
- `type: hike` = 校内课，`id` 是纯数字

### 2.5 开始刷

```bash
# 刷全部课程
python main.py

# 只刷某一门
python main.py -c 1919
python main.py -c a1b2c3d4e5f6a1b2c3d4e5f6a1b2c3d4

# 只刷某几节视频
python main.py -c 1919 -v 604 1989
```

运行时你会看到：

```
17:30:00 | INFO  | 开始共享课：中国近现代史纲要
  |__章节 第一章 进入近代中国
  |  |__课时 1.1 鸦片战争前的中国
  |  |  |__视频 导论
17:30:02 | INFO  | 学习中 导论 | 0/1220s | 目标 1111s
导论 |######################                    | 45.2% 完成
```

**进度条跑完 = 这一节刷完了。** 程序会自己跳到下一节。

想中途停下：按 `Ctrl+C`。下次运行会从断点继续（进度存在服务器上）。

## 3. 配置文件详解

`config.yaml` 的每一段都在下面。**标了「常用」的才需要动。**

### auth — 登录

```yaml
auth:
  username: ""          # 账号，留空则扫码
  password: ""          # 密码，留空则扫码
  use_qr: true          # 【常用】true=扫码登录
  save_cookies: true    # 保存登录态，下次免登录
  qr_in_terminal: true  # 在终端打印二维码
```

### study — 学习行为

```yaml
study:
  speed: 0              # 【常用】播放速度。0=用默认 1.25x。
                        # 想快可以填 1.5，但别更高 —— 会被风控抓
  end_threshold: 0.91   # 进度到 91% 就算完成（智慧树自己的判定线）
  tree_view: true       # 打印课程目录
  progress_view: true   # 显示进度条
  prime_video: true     # 拉一次视频流，制造真实的播放流量痕迹
  initial_report: true  # 进视频时先发一次初始化上报（网页端也会发）
  quiz_delay: [2, 6]    # 弹题出现后隔几秒才作答（模拟人类读题）
```

### budget — 时长纪律（**最重要的一段**）

```yaml
budget:
  session_minutes: [95, 160]   # 【常用】单次连续学习上限（随机取区间内的值）
  rest_minutes: [20, 55]       # 【常用】到点后强制休息多久
  daily_minutes: 250           # 【常用】一天最多学多少分钟
  daily_sessions: 4            # 一天最多几次会话
  per_course_minutes: 0        # 单门课的时限，0=不限
```

**为什么要有上限？**

真人不可能连续在线 8 小时、一天刷 10 小时课。
服务端风控判"异常"最安全、误伤率最低的一维就是**时长**。
把这些值调高不会让你更快刷完，只会让你更快被封。

建议：`daily_minutes` 别超过 300。

### pacer — 上报节拍

```yaml
pacer:
  max_speed: 1.5              # 速度硬上限，超过会被夹回来
  default_speed: 1.25         # speed=0 时用这个
  report_interval: [22, 47]   # 【常用】两次上报之间隔多少秒（随机）
  pause_chance: 0.0025        # 每秒触发一次"暂停"的概率
  pause_seconds: [10, 70]     # 暂停多久
  inter_video_rest: [4, 90]   # 两个视频之间休息多久
  real_millisecond_ts: true   # 【别动】false 会退化成一眼假的机器人时间戳
```

如果你频繁遇到验证码，**把 `report_interval` 拉宽**：

```yaml
  report_interval: [25, 70]     # 更松散
```

### relay — 验证码自动处理

```yaml
relay:
  enabled: true
  headless: false              # 【常用】false=看得见浏览器窗口（推荐）
  wait_captcha_seconds: 75     # 等验证码出现的上限
  manual_wait_seconds: 300     # 自动识别失败后等你手动滑的时间
  beep_on_manual: true         # 需要你动手时响铃提醒
  slider_offset_fix: -8        # 滑块总差一点时调这个（见排错手册）
```

**服务器（无显示器）配置：**

```yaml
relay:
  headless: true
  manual_wait_seconds: 0       # 没法手动接管，直接放弃
  beep_on_manual: false
```

### notify — 通知（可选）

```yaml
notify:
  serverchan_key: ""        # Server酱，微信收通知
  dingtalk_webhook: ""      # 钉钉机器人
  telegram_bot_token: ""    # Telegram
  telegram_chat_id: ""
  local_beep: true          # 本地响铃
```

挂机时推荐至少开一个 —— 需要你处理验证码时能第一时间知道。

### ai — AI 课程答题（可选）

```yaml
ai:
  enabled: false            # 【常用】要用 AI 课答题就改 true
  backend: zhidao           # zhidao=用智慧树自带大模型（不用额外 key）
  skip_exam: false          # true=只刷视频不做题
```

详见 [第 6 节](#6-ai-课程答题)。

## 4. 常见场景配方

### 只要刷某一门课

```bash
python main.py -c 1919
```

### 今天只想刷半小时

```bash
python main.py -c 1919 -l 30      # 单门课最多跑 30 分钟
```

或者改配置：

```yaml
budget:
  daily_minutes: 30
```

### 只剩几节没刷，只刷那几节

在课程页面 URL 里找 `videoId`（共享课）或 `fileId`（校内课）：

```bash
python main.py -c 1919 -v 604 1989 3120
```

### 挂一晚上，但要安全

```yaml
budget:
  session_minutes: [100, 130]    # 每段 2 小时左右
  rest_minutes: [30, 50]         # 休息半小时
  daily_minutes: 300             # 一天最多 5 小时
  daily_sessions: 3              # 最多 3 段

pacer:
  report_interval: [25, 60]      # 节拍更松

study:
  speed: 1.25                    # 保守速度
```

这样它自己会：学 2 小时 → 休息 40 分钟 → 学 2 小时 → ……到 5 小时收工。

### 走代理

```yaml
proxies:
  http: "http://127.0.0.1:7890"
  https: "http://127.0.0.1:7890"
```

或者命令行：`python main.py -c 1919 --proxy ...`（exe 同理）

### 多账号

每个账号一个目录，各自一份 `config.yaml` 和 `state/`：

```
D:\zhs\账号A\   ← 完整一套
D:\zhs\账号B\   # ← 完整一套
```

> ⚠️ 同一个 IP 同时跑多个账号是最容易被一起封的操作。
> 如果一定要多开，给每个账号配不同的代理，并且错开时间。

## 5. 人机验证与风控：你需要知道的全部

这是这个工具存在的理由，值得花三分钟读完。

### 5.1 那个验证码到底是什么

服务端在学习上报接口上返回 `code: -12`，网页端收到后弹出滑块/点选框。
**这不是"检测到你是机器人"，是"这个会话行为可疑，需要你证明一下"。**

它和普通网络错误不同，属于**可恢复状态**：
人工（或自动）过掉之后，服务端给这个会话下发新凭证，上报就恢复了。

### 5.2 程序怎么处理它

```
上报请求 → 服务端返回 -12
   ↓
自动启动一个真实浏览器（用你现有的登录态）
   ↓
打开学习页，等验证码弹出来（最长 75 秒）
   ↓
自动识别：滑块 → 算缺口位置 → 拟人轨迹拖动
         点选 → 识别文字 → 按提示顺序点击
   ↓
过掉了 → 把浏览器的新 Cookie 合并回主程序
        → 重新加密请求、重发刚才那次上报 → 继续刷
   ↓
识别失败 → 响铃 + 推送通知，浏览器窗口开着等你手动滑一下（默认等 5 分钟）
```

**全程不需要你干预。** 你只会收到几条日志，和你手动去网页上滑一次没区别。

### 5.3 怎么判断节拍真的生效了

```bash
python main.py --budget
```

会打印上报间隔的直方图：

```
  22.0~ 26.2s | #################### 412
  26.2~ 30.3s | ################## 386
  30.3~ 34.5s | ################# 361
  ...
```

**这应该是一条铺开的分布**。如果你的直方图是立在一根柱子上的（比如全在 30 秒），
说明节拍没生效 —— 那就要检查配置了。

原版 `fuckZHS` 就是这个问题的极端形态：所有上报精确落在 30.000 秒。

### 5.4 出现下面情况，说明该停手了

| 现象 | 含义 | 怎么办 |
|---|---|---|
| 偶尔一次验证码，自动过掉后继续 | 正常 | 不用管 |
| 一小时内触发 3 次以上 | 行为特征还是太明显 | 停一天，把 `daily_minutes` 降到 150 |
| 过完验证码还是 -12 | 已经进重点观察名单 | **今天别刷了**。程序会自动停 |
| 提示"风控锁定" | 同上 | 停 1~3 天 |

程序有硬上限：单次运行触发验证码超过 15 次会自动停手并通知你。
这是防止"和风控死磕"——越磕特征越明显。

### 5.5 哪些操作会让验证码暴增

- ❌ 用 `-s 3` 以上的超高倍速
- ❌ 把 `daily_minutes` 调到 600 以上
- ❌ 同一 IP 同时跑多个账号
- ❌ 每天固定时间、精确到分钟地开始刷
- ❌ 频繁换代理 IP（尤其是不干净的机房 IP）

## 6. AI 课程答题

AI 课（`kg-ai-run.zhihuishu.com` 那套）和普通课不一样：
按**知识点 + 资源**推进，每个知识点带一次小测。

### 开启

```yaml
ai:
  enabled: true
  backend: zhidao     # 用智慧树自带的大模型，不需要额外 API key
```

然后：

```bash
python main.py -ai <课程ID> <班级ID>
```

两个 ID 都在 AI 课程页面的网址里。

### 想用自己的大模型

```yaml
ai:
  enabled: true
  backend: openai
  openai:
    base_url: "https://api.deepseek.com/v1"
    api_key: "sk-你的key"
    model: "deepseek-chat"
    stream: false
```

任何 OpenAI 兼容接口都行（DeepSeek、Moonshot、本地 vLLM…）。

### 只想刷视频不做题

```yaml
ai:
  skip_exam: true
```

或者临时：`python main.py -ai 114514 4444 --no-exam`

### 答题准确率怎么保证

程序会把每次考试的**正确答案**存进 `state/answers/<课程ID>.json`：

- 第一次：AI 猜 + 交卷后服务端会返回每题的正确选项
- 从第二次起：直接命中缓存
- 同一个知识点反复考不会错同样的题

掌握度低于 30 分且已尝试 4 次以上时会放弃该知识点，不会无限重试。

## 7. 排错手册

### 启动类

**双击 exe 一闪而过 / 没有任何窗口**

用命令行启动，这样能看到错误信息：

```powershell
cd C:\你放exe的目录
.\zhs-ghost.exe
```

**提示 `找不到 config.yaml`**

exe 会自动生成。如果没有，手动从 `config.example.yaml` 复制一份改名成 `config.yaml`。

**提示 `relay.enabled=true 但未安装 playwright`**

- exe 版：你下的是 lite 版。要么换完整版，要么把配置里 `relay.enabled` 改成 `false`
- 源码版：`pip install playwright && python -m playwright install chromium`

**exe 能启动，但某个功能不工作**

先跑组件自检，它会逐项检查打包是否完整：

```powershell
.\zhs-ghost.exe --selfcheck
```

输出里带 `[!!]` 的行就是缺什么。正常应该长这样：

```
组件自检 · 完整版 · variant=full
  [ok]  配置解析       yaml
  [ok]  请求加密       Crypto.Cipher.AES
  [ok]  浏览器中继      playwright
  [ok]  验证码识别      ddddocr
  [ok]  OCR 推理引擎    onnxruntime
--------------------------------------------------------------------
  [ok]  系统浏览器      msedge → C:\Program Files (x86)\...\msedge.exe
自检通过
```

如果「系统浏览器」那行是 `[!!]`，说明你的 Edge 被卸载或损坏了，
跑一次 `zhs-ghost.exe --install-browser` 装一个内置内核即可。

**双击 exe 窗口一闪就没了**

用命令行启动就能看到错误信息（双击时程序结束窗口会自动关闭）：

```powershell
cd C:\你放exe的目录
.\zhs-ghost.exe
```

### 登录类

**二维码不显示 / 显示成乱码**

去看 `state/login_qr.png`，用手机扫这个文件。

**`账号或密码错误`**

密码模式失败。改用扫码：配置里把 `use_qr` 改成 `true`。

**`失败次数过多，需要验证码 —— 请改用二维码登录`**

智慧树对密码登录限流了。等 30 分钟，或者直接扫码。

**`该账号需要短信验证`**

先用浏览器正常登录一次智慧树，把设备加进白名单，再回来扫码。

**`cookie 里没有 CASLOGC，无法解析 uuid`**

`state/state.json` 坏了。删掉它重新扫码。

### 运行类

**一直卡在"学习中"，进度条不动**

按 `Ctrl+C` 停下，看日志里最后几行有没有 WARNING。
常见原因是课程 ID 不对 —— 校内课是纯数字，共享课是带字母的长串，搞反了会静默卡住。

**`openExam failed` / `交卷失败`**

AI 考试相关的接口。看是不是断网了，或者该知识点已经考完了。

**进度涨得比预期慢**

这是**设计如此**。`speed=1.25` 意味着 100 分钟的视频要跑 80 分钟真实时间，
再加上：
- 每两个视频之间随机休息 4~90 秒
- 每 400 秒左右随机暂停一次（10~70 秒）
- 每 95~160 分钟强制休息一次

这些"慢"换的是不被风控盯上。想快，改 `study.speed` 到 1.5 —— **不能更高**。

**提示 `今日已学习 X 分钟，达到上限，收工`**

不是错误，是配额用完了。想继续就改 `budget.daily_minutes`。
但建议别改，第二天自动重置。

### 验证码类

**滑块总是差一点 / 拖过头**

调 `relay.slider_offset_fix`：

```yaml
relay:
  slider_offset_fix: -8     # 默认。总拖不到 → 调大（比如 -2）
                            # 总是冲过头 → 调小（比如 -14）
```

**点选验证总是失败**

点选识别需要 `ddddocr`。确认装了：

```bash
pip install ddddocr opencv-python
```

装完还不行的话，把 `relay.manual_wait_seconds` 调到 `600`，
出现点选时手动点一下（会响铃提醒）。

**浏览器窗口弹出来了，但里面什么都没有**

那个页面是学习页，验证码可能延迟几秒才出现。等一会儿。
如果一直不出现，通常是这个账号当前没有风控状态 —— 程序过一会儿会自己重试上报。

**希望完全不要弹浏览器窗口**

```yaml
relay:
  headless: true
```

但注意：无头浏览器的指纹特征明显更差，**更容易被再次判定为可疑**。
有头模式（能看到窗口）成功率明显更高。

### 性能类

**日志文件涨得很快**

```yaml
log:
  level: "WARNING"     # 从 INFO 改成 WARNING
```

默认保留 14 天，会自动清理。

## 8. 退出码与文件说明

### 退出码

在脚本里调用时可以用来判断结果：

| 码 | 含义 | 建议动作 |
|---|---|---|
| `0` | 正常完成（含配额用尽正常收工） | — |
| `1` | 运行失败 | 看日志 |
| `2` | 登录问题 | 重新扫码 |
| `3` | 人机验证未能通过 | 人工处理一次，或今天就停 |
| `4` | 风控锁定 | **停 1~3 天** |
| `130` | 用户按了 Ctrl+C | — |

### 目录结构

```
你的目录/
├── zhs-ghost.exe          主程序
├── config.yaml            你的配置（含账号，别分享出去）
├── courses.json           --fetch 生成的课程清单
├── state/
│   ├── state.json         登录态 + 配额 + 浏览器指纹
│   ├── login_qr.png       最近一次的登录二维码
│   ├── answers/           AI 考试的答案缓存
│   └── browser_profile/   过验证码用的浏览器指纹（别删，删了会重新被当新设备）
└── logs/
    ├── zhs-ghost_2026-10-10.log    完整日志
    └── risk_2026-10-10.log         只含风控事件
```

### 出问题时该删什么

| 症状 | 删掉 |
|---|---|
| 登录一直失败 | `state/state.json` |
| 配额乱掉了 / 想立刻重置今日用量 | `state/state.json` |
| 过验证码总失败，像被当成新设备 | `state/browser_profile/` |
| 想彻底重来 | 整个目录删掉重下 |

> `config.yaml` 里存着你的账号，**不要发给别人，不要提交到 git**。
> 仓库的 `.gitignore` 已经排除了它。

### 想看清楚它在干什么

```bash
python main.py -d -c 1919      # -d = DEBUG 日志，会打印每个请求
```

DEBUG 日志会包含**账号信息**，只在自己电脑上看，别贴到网上。
